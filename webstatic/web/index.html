Selected motor · feedback filters
Waiting for filter readback

LPF smooths the feedback used by PID. Lower cutoff adds smoothing and delay, which can worsen overshoot. HPF affects only derivative damping; it never removes DC position holding. Start with HPF off. Raw feedback still drives travel cutoffs and safety checks.

Pause and turn jog mode off to apply. Per-motor cutoffs save for restart in SimSync; Arduino EEPROM does not store them. Updated firmware is required.

Stability ladder · change one variable at a time

Use Run only this motor. Start at the last stable PWM cap, Ki = 0, and small ±4–8 count steps. If it chatters at rest, check raw feedback and try a 1–2 count deadzone before strong filtering. A feedback LPF trial around 80 Hz is a starting experiment, not a guaranteed tune; keep HPF off.

Raise PWM max by 5–10 counts, then repeat both step directions with the same gains. Keep the change only if holding is quiet and ringing dies out. If overshoot grows, return to the last stable cap, add Kd in small increments and retest. Once the higher cap is stable, increase Kp about 5% and retest. Do not jump PWM 100 → 200 or increase PWM and Kp together.

Repeat at several positions under your operating load; monitor current and temperature. More PWM is useful only when the measured response needs it. If a limit does not settle or the guard trips, roll back. Lower LPF/raising HPF can remove useful damping—retune after any filter change.

Recommended PD sequence
01Protect

Pause output, verify feedback direction, center, host bounds, and clip margins.

02Find Kp

Set Ki = 0 and run a 4–8 count step. Increase Kp until motion is quick but just short of ringing.

03Add Kd

Repeat the same step and increase Kd until overshoot and ringing are controlled. Stop if PWM clips.

04Validate

Run both step directions, then a slow signal. Keep the gains that settle without sustained PWM saturation.
