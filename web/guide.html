Start with one motor. Build a quiet, repeatable response. Then bring the whole rig into the game.

Support the rig before solo tests: the other motors lose drive. Keep a hardware power stop within reach. This guide sends no motor commands.

THE ROUTE TO YOUR FIRST SESSION

Six checks, in order.

  1. 01

    Start paused, in bench mode

    Run ./simsync --no-udp and open Motor Tuning. Use the updated SMC3 firmware for LPF/HPF. Keep motor power off during uploads and wiring changes; close other serial apps.

    Continue when: controller readback is live and output is paused.
  2. 02

    Set each motor’s real travel

    With motor power off, check that each pot follows its own mechanism smoothly. In Motor limits, set a usable min, max and center clear of physical stops. Keep host bounds at least 4 counts inside input clipping, and clipping inside the cutoff window. Apply Limits while paused.

    Use actual center at the mechanical neutral. Display range only changes angle labels—it does not limit travel.

    Continue when: feedback and target are inside the configured host range.
  3. 03

    Check direction before PID

    Test one unloaded motor with short, low-PWM open-loop jogs. Positive jog must increase that motor’s feedback; negative must decrease it. If reversed, cut power and correct drive/feedback direction. Turn jog mode off before closed-loop tests.

    Continue when: both directions agree and the correct feedback channel moves.
  4. 04

    Make small steps settle

    Choose Run only M1/M2/M3. Use the last stable PWM cap and gains, with Ki = 0. Test +4–8 counts, then the same negative step. For a fresh motor, start conservatively; another motor’s preset is not a verified tune.

    Increase Kp about 5% at a time. If ringing grows, restore the last stable setting, then try a little more Kd. Only raise PWM max when the response needs more drive: add 5–10 counts and retest before changing gains. Keep filters fixed during comparisons.

    Continue when: holding is quiet and both steps settle without growing oscillation or a fault.
  5. 05

    Validate beyond the center

    Repeat for each motor, several positions and your operating load. Try a slow sine signal within the verified range. Watch tracking, current and temperature; check that PWM does not stay at its cap. Pause before changes. Apply saves settings for restart; browser profiles save drafts.

    Continue when: the rig tracks smoothly through its intended travel under load.
  6. 06

    Bring in the game gently

    Pause, then restart SimSync without --no-udp. Configure your game’s telemetry for SimSync’s UDP port (default 20777). While paused, lower Motion Mapping gains; mapped targets must stay inside each motor’s verified host bounds.

    Confirm live telemetry, then Resume: this enables all included motors. Start with a slow test drive. Check braking, turning and bumps produce the expected motion. Increase one game-motion gain at a time; keep the motor PID tune fixed.

    Ready for gaming when: direction, travel, settling and temperature remain acceptable during representative driving. If not, pause and return to the relevant check.
FILTER REFERENCE

Less noise, without too much delay.

Feedback LPF
Smooths the position signal used by PID. Lower Hz means more smoothing and more delay. Too much can worsen overshoot.
Derivative HPF
Removes slow components from derivative damping only. It never removes position holding. Leave it off initially; raising it can remove useful damping.
Deadzone
Allows a small position tolerance. Try 1–2 raw ADC counts for tiny holding chatter before heavy filtering.

Starting experiment: last stable PWM, HPF off, LPF around 80 Hz. Apply while paused, then repeat the same steps. This is a trial, not a universal tune.

0 Hz bypasses either filter. Cutoffs are per motor; Apply Filters saves them to SimSync, not Arduino EEPROM. Raw feedback still drives safety cutoffs. Plot feedback is quantized in 4-count increments, so tiny jitter may be invisible.

PID REFERENCE

Pull, correct, and damp.

P · Kp
Pushes toward the target. More can make motion quicker, but too much causes overshoot or oscillation.
I · Ki
Corrects persistent error over time. Start at 0. Add only a little after PD is stable and a meaningful offset remains.
D · Kd
Adds damping to motion. Small increases can reduce overshoot; too much makes feedback noise more noticeable.

PWM max is a drive ceiling, not damping. If the motor never reaches the old cap, raising it will not improve that response. Avoid jumping from 100 to 200.

Keep the same motor, step size, direction, PWM and filters when comparing gains. Aim for consistent settling—not the biggest P number. PWM frequency changes switching timing; it is separate from PWM max. M1/M2 share their frequency timer.

WHEN SOMETHING FEELS WRONG

Change the cause, then retest.

Buzzing at restCheck pot wiring and mechanical play. Try a small deadzone or gentle LPF; excessive Kp/Kd can also chatter.

Overshoot after more PWMRestore the previous cap. Retune damping at the stable cap, then increase drive gradually.

Motion runs away / a guard tripsStop and inspect feedback direction, coupling and gains. Do not repeatedly clear the fault and retry.

Game motion is harsh, bench tests are goodReduce game-motion gains and travel limits first. Preserve the verified motor tune.
